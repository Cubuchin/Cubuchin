## Overview

This case study summarizes representative work across Tier II IT support, endpoint and identity administration, phishing-defense support, network and event review, security-conscious documentation, user education, and lightweight workflow automation.

The examples are intentionally generalized. They demonstrate capabilities and problem-solving approaches without publishing employer-confidential information, internal diagrams, real records, credentials, or sensitive environment details.

## Endpoint, Identity, and User Support

Representative responsibilities included:

- Troubleshooting hardware, software, identity, endpoint, and network issues across Windows and macOS environments
- Supporting Microsoft 365 users, groups, access, and recurring account-administration processes
- Managing endpoint configuration, hardening, patching, and inventory consistency through mobile-device and endpoint-management tools
- Reconciling mismatches across identity, device, and administrative records
- Explaining technical and security-related issues clearly to nontechnical users

## Security Operations Support

Representative work included:

- Reviewing phishing reports and helping users recognize suspicious messages and requests
- Monitoring network health and security telemetry in Cisco Meraki environments
- Performing basic log and event review, documenting findings, and escalating unusual activity
- Applying MITRE ATT&CK concepts to improve the clarity and consistency of security reporting
- Supporting endpoint-security baselines, patching, and safer account practices
- Creating repeatable procedures for common support and security workflows

## Documentation and Training

I developed and improved practical guides for recurring operational tasks, including:

- User onboarding and offboarding
- Pre-event technology preparation
- Network and audiovisual setup
- Account and access processes
- Security-conscious troubleshooting
- Escalation and handoff expectations

The goal was to reduce ambiguity, improve consistency, and help users complete routine tasks with less dependence on one person’s memory.

## Event Metrics Workflow

I created a lightweight reporting workflow using:

- Microsoft Forms for structured data collection
- Microsoft Lists for centralized tracking
- Power Automate for repeatable data movement and process steps
- Power BI for concise outcome reporting

The workflow helped transform scattered participation information into a more consistent, reviewable process for communicating event activity and outcomes.

## Problem-Solving Approach

Across these projects, I generally follow the same pattern:

1. Clarify the user, operational, and security problem
2. Identify where information or responsibility is getting lost
3. Standardize the minimum useful process
4. Automate repetitive movement or reporting where appropriate
5. Keep human review for decisions that require context
6. Document the workflow so it can be repeated and improved
